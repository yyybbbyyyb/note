

## 概述

整体链路：
1. Action / actionId / 参数
2. `FrameManager` 统一跳转入口
3. `CommFrameFactory` 按 actionId 分发
4. 拉起 Activity 或复用已有 `OnePageActivity`
5. `OnePageActivity` 根据 actionId 创建 Fragment
6. `OnePageFragmentFactory` 反射调用 `Fragment.newInstance(Bundle)`


几个核心类/概念：

| 概念                     | 理解                                  | 典型代码位置                             |
| ---------------------- | ----------------------------------- | ---------------------------------- |
| Action                 | 数据协议里的跳转动作，通常来自服务端或业务 ViewModel     | 各种 ItemInfo.action、Action.actionId |
| actionId               | 页面路由 ID，比如详情页、首页、半屏页                | ActionId.java                      |
| ActionValueMap         | 跳转参数 Map，里面放 cid、vid、tabId、来源参数等    | ActionValueMap.java                |
| FrameManager           | 全局跳转门面，所有跳转尽量汇聚到这里                  | FrameManager.java                  |
| CommFrameFactory       | 具体跳转实现，按 actionId 分发到不同页面           | CommFrameFactory.java              |
| OnePageActivity        | 一页式页面容器，里面承载各种 BaseOnePageFragment  | OnePageActivity.java               |
| OnePageFragmentFactory | 根据 actionId 创建具体 Fragment           | OnePageFragmentFactory.java        |
| OpenJumpAction         | 外部拉起、Scheme 跳转的核心处理类                | OpenJumpAction.java                |
| OpenJumpParser         | 把外部 URI / Intent 解析成 OpenJumpAction | OpenJumpParser.java                |


## 内部点击跳转链路

### 1. 业务测接入

以`MediaPlayerLifecycleManager.java`为例子：
```java
public void startAction(int actionId, final ActionValueMap values) {
    ...
    FrameManager.getInstance().startAction((Activity) mCurrentContext, actionId, values);
}
```
业务侧一般发起一个 actionId + values，然后交给 `FrameManager`

### 2. FrameManager

关键方法：`public boolean startAction(Activity context, int actionId, final ActionValueMap values, IActionResultCallback callback, boolean ignoreJumpWaitTime)`

其中做：
1. 参数检查
2. 跳转防抖
3. 找注册过的 FrameFactory（目前项目中只实现了 **`CommFrameFactory`** )
4. 优先级挨个尝试


### 3. CommFrameFactory

`CommFrameFactory`的构造函数里会注册路由
```java
private void registerOnePageActions() {
    mOnePageJumpActions.put(ActionId._ACTION_COVER_ALBUM,
        ((context, id, values) -> jumpToOneDetailCover(id, context, values)));
    mOnePageJumpActions.put(ActionId._ACTION_COVER_VARIETY,
        ((context, id, values) -> jumpToOneDetailCover(id, context, values)));
    mOnePageJumpActions.put(ActionId._ACTION_FULL_COVER_DETAIL_PLAYER,
        ((context, id, values) -> jumpToOneDetailCoverFull(id, context, values)));
    mOnePageJumpActions.put(ActionId._ACTION_DETAIL_PLAYER,            
	    (context, id, values) -> jumpToOneDetailCover(id, context, values)));
    ...
```

真正执行路由：
```java
private boolean startActionImpl(final Activity context, int actionId, final ActionValueMap values, final FrameManager.IActionResultCallback callback)
```

其中的核心逻辑：
1. 先过一遍拦截器。比如登录、青少年、家长锁、权限、特殊弹窗等
2. 优先找 `mOnePageJumpActions`，找不到再找普通 `mJumpActions`。
3. 最后执行`actionJump.jump(context, actionId, values);`

以详情页跳转为例子：`jumpToOneDetailCover`
1. 是否启用全屏详情页
2. 是否来自短视频 feeds
3. 如果是，走 `jumpToOneDetailCoverFull(...)`
4. 否则走 `jumpToStandardOneDetailCover(...)`
5. `ActionValueMap extraData`转换成`Bundle data`并且塞入`OpenJumpAction.ACTION_ARGS`等字段
6. 调用 **`jumpToNormalOnePageTop`**

方法`jumpToNormalOnePageTop`：拉起 Activity 还是复用已有页面
1. 当前顶层已经是 `OnePageActivity`：在已有 `OnePageActivity` 里面新增/切换 Fragment
2. 当前没有合适的 `OnePageActivity`：走以下三种情况
	1. `startNormalOnePageActivity(context, arguments);`
	2. `jumpToNormalOnePageReOder(context, arguments);`
	3. `jumpToHomeOnePageDoubleStack(actionId, context, arguments);`

> 以上内容都是activity层次的跳转


### 4. OnePageActivity

`onCreate(...)`方法中：
1. 从 Intent 里取`OpenJumpAction.ATTR_ACTION_ID`
2. 根据 actionId 创建 Fragment：`OnePageFragmentFactory.createFragmentPage(actionId, getIntent().getExtras());`
3. `startPage(actionId, getIntent().getExtras(), mCurrentPageFragment);`
如果Activity已存在则走`onNewIntent`

`OnePageActivity.startPage`：负责Fragment 复用、新建、添加


### 5. OnePageFragmentFactory

`createFragmentPage`方法
1. 先通过`getFragmentClass(actionId, arguments)`判断目标 Fragment 类
2. 反射调用 `newInstance(Bundle)`创造 Fragment


### 6. 示例

首页海报点击跳转到详情页：
+ 首页海报点击的业务侧入口在 `LeftNavHomeBaseFragment` 的 `mOnItemClickListener.onItemClick(...)`
+ 它从 `ViewModelHolder`取出海报 `TVViewModel`
+ 再从`viewModel.getAction()` 拿到服务端下发的详情页 Action
+ 补齐首页频道和上报参数后，调用` FrameManager.startAction(...)` 进入统一跳转体系
+ 最终由 `OnePageActivity + OnePageFragmentFactory` 创建 `OneDetailCoverPageFragment`

## 外部拉起链路

外部可能来自：
1. Scheme
2. 系统 Intent
3. 第三方应用拉起
4. 语音拉起
5. Push / deeplink

整体链路：
1. 外部 URI / Intent
2. OpenJumpActivity / OpenJumpProxyActivity
3. OpenJumpParser
4. OpenJumpAction
5. doAction(...)
6. doActionImpl(...)
7. 具体 gotoXXX 或 FrameManager.startAction(...)
